# Ref-Tabs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Mehrere Ref-Tabs für H3; im Video-Batch wählt „Ref-Tab N“ über „Clip N“ den Tab pro Clip.
**Architecture:** Tabs (`H3Ref[][]`) in `DATA_DIR/ref-tabs.json`, API `/api/ref-tabs`. Formular schickt beim Start `refs` (gewählter Tab), `refTab` (1-basiert) und `refTabs` (alle). Parser ordnet jedem Clip seinen Tab zu; Server lädt alle benutzten Refs auf den Pod und speichert pro Job die tatsächlichen Refs (ohne `refTabs`).
**Tech Stack:** Next.js 16, React 19, TypeScript, vitest.
**Spec:** docs/superpowers/specs/2026-11-18-ref-tabs-design.md

## Global Constraints
- 5 Tabs Standard, höchstens 10. Grenzen pro Tab: 9 Bilder, 3 Videos, 3 Tonspuren, 12 gesamt.
- Ref-Zeile: „Ref-Tab 3“, „Reftab 3“, „Ref 3“, „Ref-Tab: 3“, Markdown-Reste (`**…**`, `#`) erlaubt, Groß/klein egal.

## Review Focus
- Ohne „---“: „Ref-Tab 3“ steht über „Clip 35“ → muss beim Trennen an Clip 35 hängen, nicht an Clip 34.
- Reihenfolge vertauscht („Clip 35“ dann „Ref-Tab 3“) → trotzdem erkannt.
- „Ref-Tab 7“ bei 5 Tabs → Fehler vor dem Start, kein Job eingereiht.
- Altes gespeichertes Formular ohne Tabs → bisherige Refs werden Tab 1.
- Gespeicherter Job enthält kein `refTabs` (Jobdateien bleiben klein).

### Task 1: Parser + Prüfungen (lib/h3refs.ts, lib/h3prompt.ts, lib/h3batch.ts)
- `parseRefTabLine(line): number | null` in h3prompt.ts.
- `tagWarnings(text, refs): string[]` und `refLimitError(refs): string | null` in h3refs.ts.
- `splitVideoBatch`: Ref-Zeile direkt vor einer Clip-Zeile wandert in den neuen Abschnitt.
- `parseVideoBatch(raw, { mode, noDialogue, tabs?, defaultTab? })`: Item bekommt `refTab: number | null`, `refs: H3Ref[] | null`; Fehler bei unbekanntem Tab oder Grenzüberschreitung; Tag-Warnungen.
- `settingsForItem` setzt `refs`, `refTab`, entfernt `refTabs`/`batchText`.
- Tests in tests/videoBatch.test.ts für alle Review-Focus-Punkte des Parsers.

### Task 2: Server (lib/server/refTabs.ts, app/api/ref-tabs/route.ts, lib/server/submit.ts, route video)
- GET → `{ tabs: H3Ref[][] | null }`, PUT `{ tabs }` mit Validierung.
- submitVideoBatch nutzt Item-Refs, `ensureRefsOnPod` für die Vereinigung; submitVideoJob entfernt `refTabs`.

### Task 3: Formular (app/video/VideoForm.tsx, RefTabs-Leiste)
- Tabs laden/anlegen (Migration), entprellt speichern, bei Fokus neu laden.
- Tab-Leiste 1…N + „+“, Batch-Liste zeigt „Tab N“, Hinweistexte.
- `?from=` Job: gleicher Inhalt → Tab wählen, sonst leerer/neuer Tab.
